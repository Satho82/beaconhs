# DEV historical missing-object exception — owner authorised 29 October 2026

This is a narrowly scoped release-policy amendment for nine previously identified missing DEV references: six attachment records, one tenant branding logo and two platform branding assets. It does not restore files, certify object completeness, authorise production use, alter any database record or replace recovery evidence. A private inventory of the original records and failed search evidence must be retained securely. Each attachment commitment binds tenant ID, attachment ID, object key, creation time, size and content type. Each branding commitment binds its reference domain, owner where applicable, branding kind and object key. The private reconciliation and owner authorisation record preserve the exact identities and evidence without publishing keys.

The exact DEV target, source and approval remain bound by existing release-admission checks. The owner-pinned approval must contain the explicit exception ID, immutable allowlist commitment, acknowledgement of outstanding loss, recovery obligation and pinned private recovery-evidence bundle checksum. The monitor must independently observe the live object references and storage inventory; it must supply each missing record's commitment, preserve the actual missing count and retain the referenced observation evidence. Unknown or duplicate identities, a tenth missing object, any mismatch, changed recovery-evidence checksum or non-DEV target fail closed. A signed web receipt records the exception ID, remaining missing count and recovery-evidence checksum; it must never describe missing data as complete.

Recover the genuine originals when an authorised source becomes available, verify identity and content before restoration, and re-run full reconciliation. Do not delete, fabricate, rename or cross tenant boundaries to satisfy the gate. A live reference/inventory probe, credible no-writer interval, backup and restore, all other security controls, and independent monitoring remain required. Passing unit tests alone is not release admission.
