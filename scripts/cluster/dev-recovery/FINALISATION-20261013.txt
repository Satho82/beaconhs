STORAGE VERIFICATION METHOD — DO NOT START ORIGINAL MINIO TO INSPECT IT
1. At the approved fenced capture only, create a private file-level manifest
   (relative path, type, size, mode, owner, timestamp, file hash, device/inode and
   link count); encrypt it with the raw retained tree. Treat paths as private.
   Reject special files, directory/file symlinks, unexpected mount boundaries,
   hardlinked payload files or inode overlap with legacy; resolve ancestor paths
   and inspect Docker/container mount namespaces. Existing scan is not repeated
   now; this additional manifest belongs to the future preservation operation.
   Source reads must use no-atime access where required; do not remount live data.
2. Verify all encrypted component checksums after independent download. Extract
   ONLY into a new private disposable destination, with path-traversal/symlink/
   hardlink rejection. Never extract over /var/lib/docker/volumes or legacy.
   Before any MinIO startup, compare the copy against the encrypted manifest.
3. Preserve one untouched verified copy. On a SECOND writable isolated copy,
   start the exact pinned MinIO image with network none/no host ports, no legacy
   mounts, no application/worker/scheduler/storage-init and no outbound callbacks.
   Startup may alter copy metadata; this is a separately approved disposable
   operation, not a non-mutating original-volume inspection. Keep both copies.
4. Recover original MinIO administrator identity from approved secret custody;
   never infer/promote the application R2 access key. No credential values in
   arguments, logs, repo or receipts. If credentials/KMS material are unavailable,
   STOP; do not reset root identity, rotate keys, initialize buckets or repair
   metadata to make inspection pass. Retained bytes alone may not include all
   required administrator/KMS secrets.
5. Use authenticated read-only S3/admin requests on the isolated copy: enumerate
   all bucket/version-list pages (including delete markers), bucket policy,
   lifecycle/versioning and encryption metadata; stat/download each required
   version and compute an actual SHA256. Multipart ETag is NOT a content hash.
   Record policy/settings privately; do not change policy, heal or resync data.
   Test application identity with read-only list/head/get and anonymous-denial
   checks; validate effective write permissions by policy review, not Put/Delete.
   Distinguish admin/root from restricted application principal and DEV bucket.
6. From the independently restored DB, enumerate every storage-bearing model,
   not just attachments: private scope review must cover documents, revisions,
   pending/deleted records and transient artifacts. Reconcile exact bucket/key/
   version, length and cryptographic content digest. Preserve unresolved/orphaned
   objects; no cleanup. If stored hashes or a trustworthy reference set are absent,
   byte preservation may PASS while logical completeness remains UNKNOWN.
7. storage_reconcile.py accepts private JSON on stdin, reports counts only, and
   fails on missing/mismatched/unexplained objects or incomplete inventory inputs.
   expected/actual rows: {bucket,key,version,bytes,sha256}; version='null' only for
   genuinely unversioned objects. Additional fields: scopeReceiptSha256,
   allPagesCollected=true, bucketMetadataVerified=true. PASS proves comparison,
   NOT independent provenance/completeness. Empty references need explicit scope
   review; a boolean/hash supplied by an operator is not an inventory collector.
